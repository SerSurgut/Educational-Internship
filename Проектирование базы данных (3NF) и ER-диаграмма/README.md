# Проектирование базы данных (3NF)

ER-диаграмма — er_diagram.pdf. Собрана из er_diagram.dot командой:

```bash
dot -Tpdf er_diagram.dot -o er_diagram.pdf
```

## Сущности

- partners — партнёры
- products — продукция
- sales — отгрузки, связывают партнёра и товар

Между партнёрами и продукцией связь «многие ко многим», поэтому она вынесена
в отдельную таблицу sales.

## Почему это 3NF

Каждое поле хранит одно значение, повторяющихся групп нет — это 1НФ.
Первичные ключи состоят из одного поля, значит зависимости от части ключа
быть не может — это 2НФ.

Для 3НФ название товара вынесено в справочник products. В исходном файле
product_name повторялся в каждой строке отгрузки, то есть зависел не от
номера отгрузки, а от самого товара. Из-за этого данные дублировались,
а переименовать товар пришлось бы сразу во всех строках истории.

## Ограничения

- partners: PK на partner_id, UNIQUE на inn и contact_email, NOT NULL на
  названии и ИНН, CHECK на рейтинг
- products: PK на product_id, UNIQUE на product_name
- sales: PK на sale_id, два FK с ON DELETE RESTRICT, NOT NULL на всех полях,
  CHECK на количество и цену

ON DELETE RESTRICT выбран, чтобы вместе с партнёром не удалилась история
его отгрузок.

Имена таблиц и полей — snake_case, таблицы во множественном числе.
