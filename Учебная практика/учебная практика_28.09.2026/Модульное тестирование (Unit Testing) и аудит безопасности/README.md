# Модульное тестирование (Unit Testing) и аудит безопасности

Приложение CRM из прошлого задания с тестами метода расчета материалов
и журналом ошибок. test_material_calculator.py — тесты на unittest,
app_log.py — запись ошибок в app.log рядом с кодом.

```bash
python3 -m unittest -v
python3 main_window.py
```

Ожидаемые результаты в тестах посчитаны вручную. Стандартный расчет:
2 × 3 × 2.35 = 14.1 на единицу, на 10 штук 141, с браком 0.1 % — 141.141,
ответ 142. Для округления взят случай с маленькой дробной частью:
5.15 × 1.0095 = 5.198925, ответ 6 — обычное округление дало бы 5.
Шестой тест — на аргументы неверного типа: строка, None, True, nan, inf
и переполнение тоже должны давать -1.

Аудит SQL: все запросы лежат в partner_service.py, и во всех значения
передаются вторым аргументом execute через %s, в том числе данные из полей
карточки партнера. f-строки в этом файле есть только в текстах ошибок.
Полей поиска и авторизации в приложении нет. Наименование
`Test'; DROP TABLE partners; --` сохраняется в базу как обычный текст.

В журнал пишется каждая ошибка, о которой приложение сообщает
пользователю. Текст исключения psycopg2 бывает многострочным, поэтому
log_error собирает его в одну строку — одна ошибка в журнале занимает
одну строку с датой и временем.
